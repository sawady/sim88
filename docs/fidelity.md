# Fidelity to MSX88

SIM88 follows MSX88 V-3.1 (R. de Diego, UPM), the simulator many computer
architecture courses use, and its assembler ASM88. Where MSX88 does something,
SIM88 does the same, even when a real 8086 would not (decision 5 in
[PROGRESS.md](../PROGRESS.md)).

This is checked against **the original program**: the programs in
[`tests/fidelity/programs`](../tests/fidelity/programs) run on MSX88, ASM88 and
LINK88 in an emulated PC ([`tools/oracle`](../tools/oracle/README.md)), and
what they did (the `.LST` listing, the registers, the flags, the memory and the
screen) is kept in [`tests/fidelity/golden`](../tests/fidelity/golden). The
test suite runs the same programs on SIM88 and compares
([`fidelity.test.js`](../src/model/__tests__/fidelity.test.js)); a program that
differs must be listed, with the reason, in
[`known-differences.json`](../tests/fidelity/known-differences.json).

## By area

"Identical" means every program of the area gives the same bytes, registers,
flags, memory and screen as MSX88.

### Assembler (ASM88)

| What | Status | Evidence |
|---|---|---|
| Encoding of every instruction form (listing bytes) | identical | `asm-encodings` and the bytes of every other program |
| `NOP` is `90h` | identical (fixed: SIM88 used `98h`, from the manual) | `nop`, `asm-encodings` |
| `DB`, `DW`, lists, strings, `DUP`, `?`, `EQU`, `ORG`, `OFFSET`, number formats | identical | `directives`, `asm-dup-counts` |

## Time: the timer and the printer

The timer's clock on MSX88 is **real time**: the same program, in fast mode,
counts 415 and 444 loop turns before the first tick in two runs
(`exp-timer-speed-fast`, `exp-timer-speed-fast-again`), and about three times
as many with COMP = 3 (`exp-timer-speed-comp3`). With an instruction-based
clock both runs would give the same count. In the slow (animated) mode a
program does not even reach `STI` in 20 seconds.

The printer also prints in real time: after four characters sent as fast as
the program can, BUSY is 1 (`exp-printer-buffer`), while one character alone
never sets it (`exp-printer-busy`).

SIM88 keeps the timer and the printer on settings of their own (frequency and
printer speed, in the interface) rather than on the wall clock; that is a
design choice of the interface, not of the model.

## Not covered yet

- What exactly the printer puts on paper (the oracle does not read the paper
  window yet), the HAND by interrupts, and the CDMA with the printer.
- The PIO in configuration 1 (printer through the PIO).
- Step by step traces (F6/F7): only the state at the end is compared.
- 8086 short forms (`A0`-`A3`, `40+r`, accumulator immediates) as raw bytes:
  ASM88 never emits them and it is not known whether MSX88 runs them.
- `BP`, `SI` and `DI` as register operands in raw bytes.
